# ハンズオン +α — 2D 版と 3D 版のパラメータ比較

**この資料は補足です。読まなくてもハンズオンは完結します。**
「もう少し触ってみたい」「3D 版の数値をいじってみたい」という方向けの手引きです。

扱うのはこの 2 ファイルです。

| ファイル | 中身 |
| --- | --- |
| `98-magic-circle-search.html` | 2D 版。3 層を CSS で同じ場所に重ねている |
| `99-magic-circle-3d.html` | 3D 版。`98` と同じ 3 層を、奥行き方向に並べて空間ごと傾けている |

---

# まず、並べて開く

2 つをブラウザの別タブで開いて、切り替えながら見てください。

- **同じもの**: 魔法陣の図形、色、線が描かれていく動き、層ごとに回る動き
- **違うもの**: 層が**奥行き方向に離れて**いて、空間全体が**手前に倒れて**いる

`99` は `98` を作り直したものではありません。
**`98` のコードをほぼそのまま残したまま、3D 空間に置き直しただけ**です。
どこが同じでどこが増えたのかを、設定値の側から見ていきます。

---

# 全体像 — 設定がどう対応しているか

`★ CONTROL PANEL` の中身を突き合わせると、3 種類に分かれます。

| | 2D 版（`98`） | 3D 版（`99`） |
| --- | --- | --- |
| **そのまま同じ** | `CONFIG`（`drawEase` / `spinEase`） | 同じ |
| | `drawDuration` / `drawStagger` | 同じ値 |
| | `spinDuration` / `spinDirection` | 同じ値 |
| **値だけ違う** | `order` / `gapToNext` | 描く順番が逆向き（後述） |
| **3D にしかない** | — | `CAMERA`（`fov` / `screenRatio` / `tiltX` / `tiltY`） |
| | — | `depth`（奥行きの位置） |
| | — | `size`（レイヤーごとの拡大率） |
| **置き場所が移った** | CSS の `--sigil-size` | JS の `CAMERA.screenRatio` |

**「時間」に関する設定はすべて同じまま**です。
増えたのは「どこに置くか・どこから見るか」という、**空間の設定だけ**です。

---

# 3D にしかない設定 ①：`CAMERA`

`99` の `★ SETTINGS` にだけあるブロックです。
**「魔法陣をどこから、どのくらいの距離で覗き込むか」**を決めています。

```js
const CAMERA = {
  fov: 35,
  screenRatio: 0.78,
  tiltX: 70,
  tiltY: 0,
};
```

| 設定 | 初期値 | 意味 | 変えるとどうなるか |
| --- | --- | --- | --- |
| `fov` | `35` | 視野角（度） | 小さくすると望遠レンズ寄りで落ち着いた見た目に。大きくすると広角になり、奥行きの誇張が強くなる |
| `screenRatio` | `0.78` | 画面の短い辺に対する魔法陣の大きさ（0〜1） | 大きくすると画面いっぱいに、小さくすると引きの絵になる |
| `tiltX` | `70` | 上下の傾き（度） | プラスで「上から見下ろす」。**`0` にすると 2D 版とほぼ同じ真正面の見た目になる** |
| `tiltY` | `0` | 左右の振り（度） | プラスで「右から回り込む」 |

## まず試すなら `tiltX`

**`tiltX` を `70` → `0` にしてみてください。**
3 層が正面を向き、`98` とほとんど同じ絵になります。
そこから `20` → `45` → `70` と戻していくと、**奥行きが生まれていく過程**が見えます。

`85` くらいまで上げると、ほぼ真横から見た「床に置かれた魔法陣」になります。

## `screenRatio` は「はみ出したら下げる」

空間を傾けると、**奥のレイヤーは上へ、手前のレイヤーは下へずれます。**
そのため見かけの縦幅は 1 枚のときより大きくなり、`tiltX` や `depth` を上げると画面からはみ出します。

**はみ出したら `screenRatio` を下げてください。** これが一番手っ取り早い調整です。

> 2D 版で同じ役割をしていたのは、CSS の `--sigil-size: min(90vmin, 1000px)` です。
> 3D では「レイヤーの寸法」ではなく「カメラの距離」で見かけの大きさが決まるため、
> 設定の置き場所が CSS から JS へ移っています。

---

# 3D にしかない設定 ②：`depth` と `size`

`LAYERS` の各レイヤーに、2 つずつ項目が増えています。

| レイヤー | `depth` | `size` |
| --- | --- | --- |
| 1（外周） | `-400` | `1.5` |
| 2（中間） | `-330` | `1.5` |
| 3（核） | `-260` | `1` |

## `depth` — 奥行きの位置

マイナスが奥（カメラから遠い）、プラスが手前です。
単位は SVG の座標と同じで、**魔法陣の直径が `1000`** に相当します。

つまり初期値の `-400 / -330 / -260` は、**直径の 1 割にも満たない間隔**で 3 枚を重ねている状態です。
`-600 / -330 / -60` のように差を広げると、層の分離がはっきりします。

**3 枚の値を全部同じ**（例: すべて `-330`）にすると、奥行きが消えて 2D 版と同じ「同一平面に重なった魔法陣」になります。

## `size` — レイヤーごとの拡大率

`1` が元のままです。外周と中間だけ `1.5` になっているのは、**奥に置いたぶん遠近法で小さく映るのを補っている**ためです。

- 見かけの大きさ = `size` と `depth` の兼ね合いで決まります
- **全体をまとめて大きくしたいときは `size` ではなく `CAMERA.screenRatio` を上げてください**

---

# 値だけ違うところ：描く順番が逆

同じ `order` と `gapToNext` という設定ですが、**2D と 3D で値が逆向き**になっています。

| | 描かれる順番 |
| --- | --- |
| **2D 版（`98`）** | 核 → 中間 → 外周（**内側から外へ**広がる） |
| **3D 版（`99`）** | 外周 → 中間 → 核（**奥から手前へ**迫ってくる） |

```js
// 98（2D）              // 99（3D）
{ order: 2, ... }  外周   { order: 0, ... }  外周
{ order: 1, ... }  中間   { order: 1, ... }  中間
{ order: 0, ... }  核     { order: 2, ... }  核
```

2D では 3 層が同じ平面に重なっているので、**内から外へ広がる**のが自然に見えます。
3D では層が奥行き方向に並んでいるので、**奥から手前へ**描いたほうが「近づいてくる」ように見えます。

**`order` の値を `98` と同じ（`2 / 1 / 0`）に書き換えれば、3D 版でも内側から描かれます。** 見比べてみてください。

## `gapToNext` は「次のレイヤーの開始時刻」

ここは 2D・3D とも考え方が同じです。

- 自分が**描き始めてから**、次のレイヤーが描き始めるまでの間隔（ms）
- 自分の `drawDuration` **より小さい** → 重なりながら描かれる
- **より大きい** → 描き終わってから間を空けて次が描かれる
- `order` が最後のレイヤーには「次」が無いので、その値は使われません

`order` を書き換えたときは、`gapToNext` も一緒にずらさないとテンポが崩れます。
（`98` と `99` で `1200 / 1000 / 0` の並びが逆になっているのはそのためです）

# コードとしての差分

設定値以外で、`98` と `99` の間で実際に変わった箇所です。

## アニメーションの書き方は、2 箇所しか変わらない

```js
// 98（2D）
animate(scene.el, {
  rotate: scene.spinDirection * 360,
  duration: scene.spinDuration,
  loop: true,
  ease: CONFIG.spinEase,
});

// 99（3D）
animate(scene.obj, {
  rotateZ: scene.spinDirection * 360,
  duration: scene.spinDuration,
  loop: true,
  ease: CONFIG.spinEase,
});
```

| 変わったところ | 内容 |
| --- | --- |
| 対象 | `scene.el`（SVG 要素）→ `scene.obj`（3D オブジェクト） |
| プロパティ名 | `rotate` → `rotateZ`（Z 軸まわりの回転、の意味） |

**それだけです。** `duration` も `loop` も `ease` も、角度を度で書けることも、そのまま通用します。
これが `D_anime-js×Three-js.md` で見た「**書き方が変わらない**」ということの実例です。

線を描くほうの `startDrawing` に至っては、**1 文字も変わっていません。**
CSS3DRenderer が HTML 要素をそのまま 3D 空間に置く方式なので、中身の SVG は DOM のままだからです。

## 増えた部品（`ENGINE` 側・触らない場所）

3D にするために足された処理は 4 つだけです。

| 部品 | 役割 |
| --- | --- |
| `setupStage()` | 空間・カメラ・レンダラーを用意し、`root` を `tiltX` / `tiltY` で傾ける |
| `resizeStage()` | `screenRatio` から必要なカメラの距離を逆算する。ウィンドウのリサイズにも追従 |
| `mountLayers()` | 各レイヤーを `CSS3DObject` で包み、`depth` と `size` を適用して空間に置く |
| `startRenderLoop()` | 毎フレーム描き直す。anime.js が数値を変え、このループが画面に反映する |

> 最後の 1 つが 3D で必須になる理由です。
> anime.js が動かしているのはあくまで**オブジェクトが持つ数値**なので、
> それを絵にするには描画を回し続ける必要があります。
> 2D 版ではブラウザが勝手にやってくれていた部分です。

## 読み込みも増える

```js
import { Scene, PerspectiveCamera, Group } from 'three';
import { CSS3DRenderer, CSS3DObject } from 'three/addons/renderers/CSS3DRenderer.js';
import 'animejs/adapters/three';
```

`importmap` にも `"three/addons/"` の 1 行が増えています。

# 触るときの注意

| やりがちなこと | どうなるか |
| --- | --- |
| CSS の `.layer { width: 1000px }` を変える | **崩れます。** SVG の `viewBox="0 0 1000 1000"` と `SIGIL_SIZE = 1000` の 3 つは必ず揃える必要があります |
| `.layer svg` に `transform` を書く | 回転が二重にかかります。3D 版の回転は three.js 側（`rotateZ`）の担当です |
| `tiltX` や `depth` を大きくした | 画面からはみ出します。`CAMERA.screenRatio` を下げてください |
| 全部大きくしたくて `size` を上げた | 層どうしの大小関係が崩れます。`CAMERA.screenRatio` のほうを上げてください |

**元に戻せなくなったら、GitHub から `99` を取り直してください。**
<https://github.com/Hol1kgmg/threejs-in-animejs-for-html>

# おすすめの遊び方

1. `tiltX` を `0` にして、2D 版と同じ見た目にしてから、少しずつ戻す
2. `depth` の差を広げて（`-700 / -350 / 0` など）、層を引き離す
3. `order` を `98` と同じにして、描く向きを「奥から」→「内から」に変える
4. `tiltY` に `20` くらい入れて、斜めから覗き込む構図にする
5. 気に入った設定にしたら、`E_ハンズオンの説明.md` の手順で**ブラウザの起動時ページに設定する**
